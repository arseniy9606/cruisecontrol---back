# Порядок показа ЛР4

1. Откройте http://localhost:8086/swagger/index.html в режиме инкогнито. Выполните POST http://localhost:8086/api/users/login с creator / Lab4Demo123. Снимите область запроса и ответа 200 с access_token.
2. Нажмите Authorize: введите Bearer, пробел, полученный JWT. Покажите каталог GET http://localhost:8086/api/fuel_consumptions (200, is_owner=1 для своих).
3. Перенесите Authorization в заголовки Insomnia/Postman; покажите полные адреса и белую галочку включения заголовка. Не заменяйте URL переменными.
4. Каталог без Authorization: 200, is_owner=0, liked=0.
5. Каталог с JWT: 200, поля is_owner/liked соответствуют пользователю. Можно также показать каталог с неверным JWT: 200 для гостя.
6. Создайте автомобиль с фото и видео. Возьмите id из ответа. Вызовите PUT http://localhost:8086/api/fuel_consumptions/11/publication (вместо 11 ваш id) без JWT: 403, пустое тело.
7. Повторите PUT с JWT и JSON {"description":"Дальняя поездка","consumption_rate":8.4,"fuel_tank_volume":60}: 200. Покажите formed_at и поля расхода/бака. Создатель назначен сервером.
8. Вызовите POST http://localhost:8086/api/users/logout с JWT. В терминале из папки проекта: docker compose exec redis redis-cli --scan --pattern 'jwt:blacklist:*'. Затем GET и TTL найденного ключа. Значение — ID, TTL — остаток срока JWT. Защищённый запрос со старым токеном: 403. Для JWT это blacklist, а не сессии.
9. Откройте docs/lab4.mdj в StarUML, диаграмму последовательности. Выберите сообщение, покажите signature: ссылка на UMLOperation домена из диаграммы классов. arguments содержит входные параметры; ответы показывают результат HTTP.

Снимайте только область запроса/ответа либо свойств StarUML. Текст должен читаться при масштабе документа 100%. ТЗ и РПЗ в комплект не входят. Реальные снимки Insomnia/Postman и окна свойств StarUML надо получить при показе на вашем экране; файлы результатов автоматических проверок их не заменяют.

# Контрольные вопросы

- Cookie — данные браузера, передаются заголовком Cookie; сервер задаёт их через Set-Cookie. Сессия — состояние на сервере, cookie содержит её ID. В выбранном варианте JWT передаётся в Authorization.
- Redis — хранилище ключ–значение; TTL удаляет запись автоматически. В ЛР4 хранит отозванные JWT до exp.
- JWT содержит header, payload и signature. Base64URL не скрывает данные. HS256 использует общий секрет; RSA применяет пару закрытого и открытого ключей. Пароли в JWT не записываются.
- Аутентификация проверяет личность по логину и паролю; авторизация проверяет права: гость читает, создатель создаёт и изменяет свои автомобили.
- Logout не меняет подписанный JWT, поэтому до истечения exp сервер проверяет blacklist.
- SSO позволяет входить в несколько систем через единого провайдера. Двухфакторная аутентификация требует два разных фактора, например пароль и одноразовый код. В ЛР4 SSO и 2FA являются вопросами теории.
