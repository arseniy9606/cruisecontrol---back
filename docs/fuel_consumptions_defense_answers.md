# Ответы на контрольные вопросы ЛР 1

## MVC и компоненты проекта

MVC разделяет приложение на Model, View и Controller. Модель описывает данные и доступ к ним, контроллер обрабатывает запрос и выбирает данные, представление показывает результат.

В проекте модель — структура `FuelConsumption` и единственная коллекция в `FuelConsumptionRepository`. Контроллеры — `GetFuelConsumptionTiles`, `GetFuelConsumptionFeed`, `GetFuelConsumptionDraft`. Представления — три HTML-шаблона. Роутер Gin связывает URL и контроллеры. Контроллер обращается к репозиторию, затем передаёт данные в шаблон. Репозиторий не зависит от HTML или HTTP.

## MVT

MVT означает Model, View, Template. Например, в Django модель представляет данные, View содержит обработку запроса и бизнес-логику, Template формирует вывод. Django View по роли близок к контроллеру MVC, а Django Template — к представлению MVC. В нашей лабораторной используется Go/Gin с MVC-подобным разделением. Знание MVT нужно для теории; Django не используется, поскольку актуальные требования курса его запрещают.

## Шаблонизация и SSR

Шаблонизация — получение итогового HTML из шаблона и данных на сервере. `{{range .FuelConsumptionCards}}` повторяет разметку для автомобилей, `{{.FuelConsumptionName}}` выводит название, `{{if ...}}` выбирает фрагмент. `ctx.HTML` передаёт данные и имя шаблона в Gin; `html/template` экранирует значения в HTML-контексте.

SSR — Server-Side Rendering: браузер получает готовый HTML. В ЛР-1 фильтрация выполняется до генерации страницы. После отправки формы браузер получает новый документ с отобранными карточками. JavaScript для этого не нужен.

## HTTP

HTTP — протокол прикладного уровня для обмена запросами и ответами. Запрос содержит метод, адрес ресурса и версию протокола, заголовки и, при необходимости, тело. Ответ содержит статус, заголовки и тело. GET используется для получения ресурса. В строгом режиме ЛР-1 операции изменения отсутствуют. В расширенной версии лайк отправляется методом POST и завершается 303 на GET ленты.

`GET /fuel_consumptions?fuel_consumptions_fuel_min=6.2&fuel_consumptions_fuel_max=6.7` получает HTML плитки. Параметры после `?` задают диапазон расхода. `GET /fuel_consumptions/feed/2?next=true` получает следующую опубликованную карточку после ID 2. ID передан в пути, `next` — параметр запроса. `GET /fuel_consumptions/draft` получает единственный черновик без входного ID.

200 означает успешный ответ, 400 — неверные параметры фильтра, 404 — карточка или маршрут не найдены. Сервер возвращает `Content-Type: text/html; charset=utf-8`. Браузер отдельно запрашивает CSS, фотографии и видео. Поэтому три GET страницы не означают всего три сетевых запроса при загрузке.

## HTTP и OSI

OSI — семиуровневая модель сетевого взаимодействия: физический, канальный, сетевой, транспортный, сеансовый, представления, прикладной. HTTP относится к прикладному уровню. IP обеспечивает сетевую адресацию, TCP — транспорт и надёжную доставку; порт 8080 определяет процесс веб-сервера, а 9000 — MinIO. MAC-адрес относится к канальному уровню.

В HTTP/1.1 и HTTP/2 обычно используется TCP. HTTPS добавляет TLS для шифрования и проверки сервера. HTTP/3 работает поверх QUIC на UDP. Модель OSI — концептуальное описание: её уровни не совпадают буквально один к одному с реализацией TCP/IP.

## Web

Web — система взаимосвязанных ресурсов в Интернете. Основные компоненты: HTML, URI/URL и HTTP. Интернет — более широкая сеть, в которой кроме Web существуют почта и другие службы. HTML описывает документ, URL адресует ресурс, HTTP передаёт его. Для динамической страницы сервер сначала формирует HTML.

## HTML и CSS

HTML — язык гипертекстовой разметки. `head` содержит метаданные и подключение CSS, `body` — содержимое. `a` создаёт ссылку, `form method="get"` — GET-форму, `input type="number"` — числовой ввод, `input type="range"` — ползунок, `input type="file"` — системный выбор файла, `video` — видеоплеер, `nav` — навигацию. CSS задаёт оформление, размеры и компоновку.

В плитке `display: grid` и `grid-template-columns: repeat(2, minmax(0, 1fr))` создают две колонки. В ленте параметры имеют `flex-direction: column`. Описание ограничено `-webkit-line-clamp: 2`, а checkbox `:checked` снимает ограничение и меняет подпись на «Меньше».

## Коллекция и первая нормальная форма

В ЛР-1 данные находятся в массиве структур в памяти, а не в БД. Два предметных поля атомарны: расход — одно число, объём бака — одно число. Нельзя хранить массив расходов или список объёмов бака внутри одной карточки. Вложенный `FuelConsumptionLikedBy` разрешён отдельно заданием: это ID пользователей, поставивших лайк. Контроллер вычисляет число лайков через `len`.

## MinIO

MinIO — S3-совместимое объектное хранилище. Бакет — контейнер объектов, ключ — имя объекта, например `fuel_consumptions_suv.jpg`. В модели хранится ключ фото и отдельный ключ видео. Контроллер добавляет базовый URL, а браузер загружает файл непосредственно из MinIO. Например, `http://localhost:9000/fuel-consumptions/fuel_consumptions_suv.mp4`. Метаданные карточки находятся в коллекции, содержимое медиа — в хранилище.

Docker Compose описывает сервис MinIO, проброс портов и volume. Volume сохраняет загруженные файлы между пересозданиями контейнера. Вспомогательный контейнер `fuel_consumptions-media-init` создаёт бакет, разрешает анонимное чтение и загружает файлы.

## Лайки без JavaScript

Форма POST /fuel_consumptions/:id/like. Cookie обозначает анонимный браузер. ID хранится во вложенном FuelConsumptionLikedBy; счётчик len вычисляет контроллер. Повторное нажатие убирает свой лайк. Мьютекс защищает общую коллекцию, JSON сохраняется через временный файл и rename. После POST сервер возвращает 303, поэтому обновление страницы не повторяет операцию. Авторизации и базы данных нет; это учебная функция, не защищённая система учётных записей.

Переменная FUEL_CONSUMPTIONS_STRICT_LAB1=true отключает POST и интерактивное сердце; остаются три GET обработчика, статический счётчик и коллекция без редактирования, как требует методичка.
