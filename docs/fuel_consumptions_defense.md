# Порядок защиты ЛР2

Открой приложение, Adminer, проект в редакторе и файл ER-диаграммы в StarUML. Запуск — `ЗАПУСТИТЬ.command` в папке «лаб2-РИП». Все SQL-блоки собраны в `fuel_consumptions_defense.sql`; выполняй нужный блок отдельно.

## До показа

1. Впиши ФИО и группу в отчёт. Данные не были указаны в ЛР1.
2. Подготовь конспекты всех пройденных лекций. Ответы на контрольные вопросы приложены; прочитай их, чтобы объяснить реализацию своими словами.
3. Покажи тему: «Транспорт», вариант 29, экономия топлива при использовании круиз-контроля. Предметные поля этого этапа — расход и объём бака.
4. Открой ветку `lab2-fuel_consumptions` в GitHub.
5. Открой `fuel_consumptions_lab2.mdj` в StarUML. Объясни PK, FK, три связи 1:N и то, что таблица лайков реализует M:N.
6. Проверь, что в БД есть опубликованные, удалённые и черновая карточки. ID 5 — подготовленный черновик; сначала опубликуй его, когда понадобится создать новую карточку. Для повторной защиты используй текущие ID из SELECT, а не слепо повторяй ID со скриншотов.

## Скриншоты 1 и 2 Панель администратора

В Adminer открой SQL-запрос. Измени статус фуры ID 4 на «удален» через UPDATE. Выполни SELECT и покажи, что строка всё ещё присутствует. Объясни: логическое удаление — смена статуса, физическое удаление не выполняется. Лайки сохраняются.

## Скриншоты 3–10 Три страницы и изменения

3. Покажи плитку, ленту и добавление. В плитке опубликованные записи, в ленте одна карточка, в добавлении текущий черновик. Дополнительные снимки 3b и 3c сохранены в комплекте.
4. Выполни фильтр расхода от 10 до 11. Объясни параметры URL и WHERE/BETWEEN в репозитории. Значения в форме сохраняются.
5. Сбрось фильтр, удали микроавтобус кнопкой «Удалить автомобиль» и покажи отсутствие карточки в плитке.
6. Открой `/fuel_consumptions/feed/3`: будет «Автомобиль не найден». При необходимости открой Network и покажи HTTP 404. Адрес с `?next=true` также не должен открывать удалённую карточку.
7. Открой добавление. Если уже есть черновик, сначала заверши его публикацию. Затем выбери фото/видео, напиши «Седан для дальних поездок» и нажми «Далее». Покажи сохранённый черновик. В Network тело POST содержит название, а не содержимое файлов.
8. В Adminer выполни SELECT черновика: есть ID, название, автор 1, дата создания, статус «черновик», неверные URL; дата формирования NULL.
9. На странице черновика заполни описание, бак 70 л и расход 6,7 л/100 км; нажми «Опубликовать». Покажи новую карточку в плитке и ленте.
10. Через SELECT покажи статус «опубликован», оба предметных поля и заполненную дату формирования. Объясни, почему POST заканчивается перенаправлением 303 на GET.

## Скриншоты 11–13 Изменения прямо в БД

11. В Adminer поменяй седану ID 1 объём бака на 75 и расход на 8,4.
12. Добавь в `fuel_consumption_likes` новую пару водитель–автомобиль, например `(1,17)`, если её ещё нет. Через COUNT(*) покажи увеличение количества строк. Первое значение — ID автомобиля, второе — ID водителя. Повтор одной пары запрещён UNIQUE.
13. Обнови ленту `/fuel_consumptions/feed/1`: появятся новые значения и новый счётчик лайков. Перезапуск сервера не нужен. В приложении нет постановки лайков — это требование ЛР2.

## Скриншоты 14–21 Код

14. `internal/app/fuel_consumptions/fuel_consumptions.go`: три модели, типы Go, column-теги и первичные ключи.
15. `fuel_consumptions_repository.go`: GORM подключается к PostgreSQL; `migrations/sql/001_schema.sql` и `cmd/migrate` создают схему отдельно от HTTP-сервера. Покажи FK RESTRICT и уникальный частичный индекс для черновиков.
16. `internal/api/fuel_consumptions_server.go`: ровно 3 GET и 3 POST. Статика отдельно. POST лайка отсутствует.
17. `PublishedFuelConsumptions`: фильтрация статуса и числового диапазона в SQL через ORM, затем Find.
18. `FeedFuelConsumption` и `DraftFuelConsumption`: ORM First с LIMIT 1. Для ленты не загружается весь массив. Переход к следующей карточке использует условие ID > текущего; после последней выбирается первая опубликованная запись.
19. `CreateFuelConsumption`: GORM Create, черновик создаётся только после «Далее», неверные URL и системные поля назначает сервер. Индекс БД не допускает второй черновик даже при одновременных запросах.
20. `PublishFuelConsumption`: GORM Updates, заполнение описания и двух предметных полей, смена статуса, дата формирования.
21. `DeleteFuelConsumption`: `sqlDB.ExecContext` с параметрами `$1`, `$2`, `$3`, SQL UPDATE и RowsAffected. Здесь не используется `gorm.Update`, `gorm.Exec` или физический DELETE.

Пять контроллеров работают через ORM: плитка, лента, черновик, создание и публикация. Шестой удаляет через прямой SQL. Скажи это явно.

## Скриншот 22 Запасные фото и видео

Открой новую опубликованную карточку либо ID 7. В исходном HTML или Network → Response покажи:

- `/fuel_consumptions-assets/defaults/fuel_consumptions_default.jpg`;
- `/fuel_consumptions-assets/defaults/fuel_consumptions_default.mp4`.

Объясни: в БД неверные URL, сервер проверяет файл в MinIO, при отсутствии подставляет локальные файлы. Они используются на всех трёх страницах. Выбранные при создании файлы не загружались и не сохранялись — этого требует текущее задание.

## Завершение

Покажи ER-схему и отдельную ветку GitHub. При вопросах запусти `ПРОВЕРИТЬ.command`: тесты работают с настоящим PostgreSQL в отдельной временной схеме. Предыдущие замечания преподавателя нужно приложить отдельным файлом с подтверждением исправлений; список таких замечаний пользователем не предоставлен. Готовое сравнение ЛР1/ЛР2 описывает реализованные изменения, но не выдаёт их за замечания преподавателя.
